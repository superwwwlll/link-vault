# 链藏笔记区（1.5.0）设计

状态：已与用户确认，进入实现。
确认时间：2026-09-28。

## 需求

新增一个笔记区，保存剪贴板里的文字、数据、密码等，并且可以搜索。

原始诉求里的「密码」是本设计的分界线：收藏和备注一直明文存在应用私有目录，
而密码一旦存进去，"别人拿到手机或备份文件"的代价就从"看到链接"变成"看到密码"。
下面每个决定都围绕这条线。

## 已确认的决定

| 议题 | 决定 |
| --- | --- |
| 密码类内容怎么存 | 主密码加密，复用仓库已有的 PBKDF2+AES/GCM 写法 |
| 内容怎么进笔记 | 手动新建/粘贴 + 首页剪贴板提示条扩展 |
| 要不要分类型 | 不分，只有一条「私密」开关，锁定显示掩码 |
| 备份范围 | 非私密笔记进 JSON 明文备份；私密笔记只进 `.lvault` 加密备份 |
| 加密放在哪一层 | Room 新表，按行加密私密笔记正文 |
| 口令数量 | 笔记主密码与 `.lvault` 加密备份口令**统一为一个** |
| 顺手加固 | 解锁期间禁止截屏（`FLAG_SECURE`） |
| 改主密码 | 要，全量重加密走一个事务，失败整体回滚 |
| 删除行为 | 笔记一律硬删除 + 二次确认，不进 30 天回收站 |
| 剪贴板残留 | 不做自动清理，但复制后如实提示会留在剪贴板 |

明确**不做**的：分类、有效期、验证码自动清空、后台剪贴板监听、笔记回收站、
笔记的 HTML/Markdown 导出。

## 一、数据结构

Room 从 v4 升到 v5，新增两张表；`Migration4To5` 只建表，**不改动 `bookmarks` 一行数据**。

- `vault` 单行表（`id` 固定为 1）：`salt` + `verifier`。
  verifier 是用主密码派生的密钥加密的一段固定魔数，作用是"没存任何笔记之前也能判断密码输对了没有"。
- `notes` 表：`id / text / cipher / private / createdAt / updatedAt`。
  普通笔记正文进 `text`（明文，与普通收藏同级）；私密笔记 `text` 留空，正文进 `cipher` BLOB。
- 单条正文上限 16,000 个 UTF-16 单元，与 `Capture.MAX_TEXT` 一致。

密文封套自描述，形状与 `SecureBackup` 一致：`魔数 + 版本 + salt(16) + iv(12) + AES/GCM 密文`。

## 二、密钥派生与多 salt

`一个密码 + 一个 salt` 走 PBKDF2 12 万次迭代派生密钥；**不能按条派生**——
50 条私密笔记各跑 12 万次迭代会让解锁卡住好几秒。

解锁时按密文头里的 salt 分组派生，密钥缓存到本次会话结束。正常情况全库只有本机一个 salt，
只派生一次；从别人备份里导进来的笔记带的是自己的 salt，那才多派生一次。

## 三、解锁会话

- 主密码**按需设置**：进笔记页不拦人，普通笔记直接可建；第一次打开「私密」开关时要求设置
  （≥8 个字符，与 `SecureBackup.MIN_PASSWORD` 一致，输入两遍）。
- 当场告知三件事：不记在任何地方、忘了无法找回、忘记后没有任何找回通道。
- 密钥只活在内存里，锁定时立即清零。
- 自动锁定：`onStop`（切后台、锁屏、离开应用）立刻锁定；笔记页另给一个手动「锁定」按钮。
- 锁定状态下私密笔记只显示「私密笔记 · 已锁定」，不泄露任何内容片段；普通笔记照常读、照常搜。
- 搜索遇到锁定时必须如实写「另有 N 条私密笔记未参与搜索」——不能让用户把"搜不到"当成"没有"。
- 解锁期间给窗口加 `FLAG_SECURE`：不能截屏、最近任务缩略图不露内容；
  代价是解锁期间自己也无法截图，这条写进界面提示。

## 四、修改主密码

设置页「修改主密码」：旧密码 → 新密码两遍 → 全部私密笔记解密后以新密钥重加密，**一个事务**。

硬规则：只要有笔记用旧密钥解不开（例如从别人的备份导进来的），改密码**直接失败并报条数**，
绝不静默跳过——跳过等于悄悄丢内容。写入失败同样整体回滚，保持原密码与原数据。

## 五、导进来的"别人家主密码"

解不开的笔记显示「无法解密：这条属于另一个主密码」，**不清除、不覆盖、不改动**，
直到用对应的主密码解锁才读得出内容。

## 六、界面

- 底部页签从 3 个变 4 个：收藏 / **笔记** / 标签 / 设置；`vm.tab == N` 的下标判断全部跟着改。
- 笔记页 = 搜索框 + 列表 + 新建按钮，卡片密度与配色沿用收藏页规范。
- 列表首行走标题，用 `Titles.collapse` 收成一行，与收藏标题同一套清洗规则，不出现换行。
- 点卡片**直接进编辑页**（正文可改 + 私密开关 + 保存），不做"详情→编辑"两屏。
- 编辑页顶部给一个「从剪贴板粘贴」按钮。
- 私密笔记默认掩码，点「显示」展开明文；复制按钮复制明文，复制后提示「已复制，会留在剪贴板直到你复制别的内容」。
- 搜索用独立状态 `noteSearch`，不触碰收藏的 `search`。
- 列表按 `updatedAt` 倒序。编辑已锁定的私密笔记前必须先解锁，界面上不给"绕过解锁"的路径。
- 首页剪贴板提示条：含链接仍走「收录为收藏」，纯文本走「存为笔记」；
  两者都必须用户点击后才落盘，沿用现有"关掉后同内容不再提示"，避免复制什么都弹。
- 纯文本候选的门槛：trim 后非空且长度 ≥ 4；与上次被关掉的那条相同则不再提示；
  提示条只展示前 80 个字符。

## 六之二、关掉「私密」开关

主密码不设"关闭加密"入口，只能改密码。但单条笔记可以把「私密」关掉：
把该条解密后写入 `text`、清空 `cipher`，等同于从加密区搬到明文区——这是用户主动降级，
界面上要如实说明"关掉后这条会像备注一样明文存在本机"。反向打开时同理加密。

## 七、备份

- JSON 明文备份 `version` 1 → 2，新增可选 `notes` 数组，**只含非私密笔记**。
  导入放宽为接受 1 和 2（v1 没有 notes 就跳过）。
  已知后果：新版导出的文件在 1.4.0 及更早版本手机上会被拒（当前校验是版本严格相等），反向没问题。
- `.lvault` 加密备份口令统一用主密码，payload 携带 `vault` 的 salt/verifier 与全部笔记
  （私密笔记按密文原样携带）。没设过主密码又要导加密备份时，现场设一个——只此一个密码。
- 笔记**不进** HTML / Markdown / 导航页导出：那三个是给人看的收藏清单。
